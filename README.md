# DeepSeek Chat Clone

A minimal clone of chat.deepseek.com with basic chat functionality using OpenAI TTS API.

## Features

- Minimal chat interface with user and assistant messages
- Automatic scrolling of chat messages
- OpenAI TTS integration
- Conversation persistence
- JWT-based authentication (signup/login)


## Tech Stack

- Next.js 14 (React + Server/Client components)
- TypeScript
- Tailwind CSS
- SQLite + Prisma ORM

## Getting Started

1. Clone the repository:
```bash
git clone https://github.com/eelyroc00/ds-clone
cd ds-clone
```

2. Install dependencies:
```bash
npm install
```

3. Initialize the database
```bash
npx prisma migrate dev --name init
```

4. Set up environment variables:
Create a `.env.local` file in the root of the project with the following content:
```
OPENAI_API_KEY=[ADD OPENAI KEY HERE]
```

5. Run the development server:
```bash
npm run dev
```

## Scaling Chat History

  * Hot/Cold Storage: keep recent conversations in primary, high-performance sharded database. This tier is optimized for fast reads and writes and strict consistency for message ordering. Redis can be used as a cache in front of this hot database to further reduce latency for frequently accessed and/or active conversations. Periodically migrate older messages from the hot tier to a separate, more cost-effective storage solution. This could be a cheaper database optimized for large-volume storage (like Apache HBase, or blob storage like Amazon S3/Google Cloud Storage with a queryable layer on top).

  * Limit the amount of data on inital load and incrementally load on user scroll.

  * Auto-delete very old messages as a data-retention policy.

## Caching Strategies
  
*  Client-side caching: 
    * Cache user profile data, recent conversations, a certain window of messages for older conversations, recently viewed media, API responses.
    * Use browser localStorage for conversation drafts and UI state
  
*  Server/database caching:
    * Add Redis as a session store and for frequently accessed and/or active conversations.
    * Implement database query caching for common chat messages like chit chat.
    * Edge caching for static assets and API responses.

## Storage Solutions for 1M+ Users

Relational databases offer strict data consistency for message ordering, but can face challenges with the high volume of message writes and horizontal scaling complexities. NoSQL databases excels at high write throughput due to their design for horizontal scalability and flexibility. For a chat application, different NoSQL models can serve distinct purposes: document databases like MongoDB allow for a flexible schema, which is advantageous for storing diverse message types or evolving user profile attributes. They can make it easier to iterate on features without rigid schema migrations. Wide-column stores such as Apache Cassandra are particularly well-suited for the immense write throughput generated by chat messages, efficiently handling time-series data and offering robust scalability across many servers. 

Sharding becomes critical. Primary message data can be partitioned by ConversationID, complemented by a secondary index or a dedicated lookup table sharded by UserID for mapping users to conversations. This approach enables highly efficient retrieval of complete conversation histories, because all messages for a specific chat are co-located on a single shard. 

Alongside sharding, replication plays a crucial role in ensuring reslience and performance. By creating and maintaining copies of data across multiple servers, replication ensures high availability, allowing the system to remain operational even if a primary server fails. Furthermore, read traffic can be directed to replica instances, significantly improving read performance for common operations like fetching conversation histories or user profiles.
